# 日报推送格式规范（2026-07-29 飞书接入版）

> 本文档是微信日报推送的**格式模板**，渲染代码在 `report.generate_push_brief()`，
> 标题逻辑在 `main.py` 推送段。改推送样式前先对照本文档；改完更新本文档。
> 注意：`reports/*.md` 的完整日报**不受本规范约束**（那是留档用的详细版）。

## 设计原则（用户明确要求）

- 推送**必须简洁**：只推「今天有什么新岗、在哪投」，不推总览表、存量计数、投递进度等一切统计信息。
- 只出现**当天有新增对口岗位的公司**；没新岗的公司完全不出现。
- 每个岗位一行，**岗位名称本身就是投递链接**（微信或飞书里点岗位名直接跳投递页）。

## 标题

| 场景 | 标题 |
|------|------|
| 有新增 | `今日新发布岗位 · 7月23日` |
| 无新增 | `今日无新增岗位 · 7月23日` |
| `--full` 初始化 | `秋招雷达初始化完成 · 7月23日` |

## 正文模板（有新增时，2026-07-23 批次22 加入评分排序）

```markdown
**💼 社招岗位**

**字节跳动**（2）
- [⭐ 内容运营（抖音电商）· 上海](https://jobs.bytedance.com/...)
- [产品经理-生活服务 · 北京](https://jobs.bytedance.com/...)

**小红书**（1）
- [增长运营-社区 · 上海](https://job.xiaohongshu.com/...)

**🎓 校招岗位**

**腾讯**（1）
- [⭐ 产品策划（2026届）· 深圳](https://join.qq.com/...)

———
📡 秋招雷达 ｜ ⭐=高度匹配 ｜ 每日 09:00 自动巡航
```

细节规则：

- **社招在前**（主战场），校招在后；哪个区没新增就整区不出现。
- 公司排序沿用 `report.COMPANY_ORDER`（官网大厂在前）；公司名后标当日新岗数 `（N）`。
- **公司内按可投程度评分排序**（scoring.score_job，高分在前）；
  评分 >= 85 的岗位加 `⭐ ` 前缀（高度匹配：方向强命中/城市匹配/应届友好/新发布的组合）。
- 校招岗位在名称后括号标届别：`（2026届）` / `（2027届）` / `（不限届别）`
  （届别列表来自 config.CAMPUS_FOCUS_YEARS，分桶用 `filters.campus_year_bucket`）；社招不标。
- 地点存在时以 ` · 城市` 拼在名称后；岗位无 url 时退化为纯文本行（不带链接）。
- 末尾固定页脚：`———` + `📡 秋招雷达 ｜ ⭐=高度匹配 ｜ 每日 09:00 自动巡航`。
- 推的岗位 = 当天新增 ∩ 已过滤对口岗（方向/城市/届别/排实习/排资深含JD经验），不是全量新岗。

## 正文（无新增时）

一句话正文，让用户知道系统活着不是坏了：

```
今日各源均无新增对口岗位。系统运行正常，有新岗放出会在次日推送。
```

## 推送通道

- Server酱（`PUSH_KEY`，支持逗号分隔多个 SendKey = 推多个微信），正文按 markdown 渲染，链接可点。
- 正文超 30000 字符会被 push.py 截断（Server酱上限约 32KB），精简版正常远达不到。
- 飞书群自定义机器人（`FEISHU_WEBHOOK`，填写完整 webhook URL），正文使用 Markdown 卡片渲染，链接可点。
- 飞书卡片标题固定以 `岗位推送｜` 开头，以满足机器人安全设置中的“岗位”关键词；正文按 UTF-8 字节安全截断，为飞书 20KB 请求体限制预留空间。
